# 가인 GA;IN

음악 동호회 가인의 공개 홈페이지와 운영진 관리 화면입니다.

공개 주소: https://gain-music-club.vercel.app

## 개발

Node.js 22 이상과 pnpm을 사용합니다.

```sh
pnpm install
pnpm dev
pnpm test
pnpm build
```

환경 설정이 없으면 확인된 소개와 빈 콘텐츠 상태를 표시합니다. 저장 기능이 로컬 저장소로 대체되지 않으며, `/admin`에는 연결 대기 안내가 표시됩니다.

## Supabase 연결 (Free 전용)

1. 사용자 소유의 Free 조직에 `gain` 프로젝트를 생성합니다. 기존 다른 앱의 프로젝트는 사용하지 않습니다.
2. SQL Editor에서 `supabase/schema.sql`을 실행합니다.
   이어서 `supabase/seed-welcome-notice.sql`을 한 번 실행해 첫 사용 안내 공지를 등록합니다. 연결 전에는 동일한 공지가 정적 기본 콘텐츠로 표시되며, 연결 후에는 DB의 공지를 사용하므로 운영자가 수정·삭제할 수 있습니다. 앱이 삭제한 공지를 자동으로 재생성하지 않습니다.
3. Authentication > Sign In / Providers에서 신규 가입을 비활성화합니다.
4. Authentication > Users에서 운영진 이메일·비밀번호 계정을 생성합니다. 비밀번호는 사용자 본인이 정하며 소스나 문서에 기록하지 않습니다.
5. SQL 파일 마지막의 `gain_admins` 등록 예문에 실제 운영진 이메일을 넣어 실행합니다. 일반 인증 계정만으로는 쓰기 권한이 생기지 않습니다.
6. `.env.example`을 `.env.local`로 복사하고 프로젝트 URL과 publishable/anon 키를 입력합니다. service_role/secret 키를 VITE 환경 변수에 넣지 않습니다.
7. 로컬 서버를 재시작하고 빌드 후 재배포합니다.

모든 콘텐츠와 업로드 이미지는 공개용입니다. 비공개 개인정보를 올리지 마세요. 삭제는 되돌릴 수 없으며, 데이터와 사진은 정기적으로 별도 보관하세요.

## 관리

`/admin`에서 로그인 후 일정·공연·공지·앨범과 소개·가입 안내를 편집합니다. 사진 앨범은 먼저 제목과 내용을 저장한 뒤 수정 화면에서 사진을 추가합니다. 대표 이미지와 포스터는 작성 중 업로드할 수 있습니다. 날짜는 한국 시간입니다. 영상은 HTTPS 유튜브·인스타그램 링크만 지원합니다.

## 무료 운영

- Vercel Hobby: 비상업 동호회 안내만 운영하며 `vercel.app` 기본 주소를 사용합니다.
- Supabase Free: DB 500MB, 파일 1GB, 전송량 등 무료 한도 내에서 운영합니다. 계정의 다른 사용량도 함께 확인하세요.
- 사진은 긴 변 1600px 이내 WebP로 압축하며 업로드 1개당 최대 2MB입니다. 가인 저장소가 800MB 이상이면 추가 업로드를 제한합니다. 이 제한은 여유 공간 확보용이며 동시 업로드까지 포함한 계정 전체 한도 보장은 아닙니다.
- 무료 프로젝트는 저활동 시 일시 정지될 수 있습니다. Supabase 대시보드에서 Resume/Restore 후 상태를 확인하세요. 유료 업그레이드는 하지 않습니다.
- 무료 한도에 도달하면 사진 정리·사용량 감소·한도 초기화를 기다리는 방법으로 대응합니다.

## 배포

일반적인 Vercel Git 배포에는 루트 `vercel.json`을 사용합니다. Vite 프레임워크, `pnpm build`, `dist` 출력 폴더로 구성합니다.

이번 배포는 로컬에서 빌드한 공개 정적 파일만 API로 올렸습니다. `scripts/deploy.mjs`는 Windows Vercel CLI의 기존 로그인 정보를 메모리에서 읽고, `kimeunyeols-projects`가 Hobby 플랜인지 확인합니다. 토큰은 출력하거나 프로젝트에 저장하지 않습니다.

```sh
pnpm build
node scripts/deploy.mjs
```

배포 결과는 무시되는 `.vercel/deployment.json`에 기록됩니다. 프로젝트 소스·환경 파일·원본 대공연 포스터는 정적 배포에 포함되지 않습니다.

## 검증 상태

타입 검사, 프로덕션 빌드, 달력 윤년·한국 시간 변환·안전한 외부 링크 테스트를 포함합니다. 실제 운영진 저장 및 익명 사용자 쓰기 차단 검증은 Supabase 프로젝트 연결 후 수행해야 합니다.

## 운영 개선 검증과 반영 절차

2026-10-02 재확인한 환경 분리, 배포 관문, 감사, 릴리스/SQL 이력, 배포 후 확인과 롤백은 [운영 절차](docs/OPERATIONS.md)를 따르세요. 기존 배포 완료 기록은 과거 시점의 결과입니다. 이번 운영 개선 코드는 아직 운영에 반영하지 않았습니다.

## WSL 공통 표준과 안전 모드 (2026-10-03)

개발 명령과 권한·무료 한도 기준은 [공통 표준](docs/DEVELOPMENT_STANDARD.md), 구현과 운영 미확인은 [보안 검토](docs/SECURITY_REVIEW.md)를 따릅니다. `pnpm verify`와 `pnpm audit --audit-level=high`로 검증합니다. 기본값은 외부 연결 없는 공개 콘텐츠입니다. 기대 프로젝트를 설정해도 익명 읽기만 가능하며 로그인·저장·업로드는 검증 전 차단됩니다. 기존 `public.photos`와 충돌하지 않도록 새 검토안은 `gain` 스키마와 별도 버킷을 사용합니다. 기존 README의 public schema 초기 설정 예시를 공유 프로젝트에 적용하지 마세요. 검토 SQL은 운영에 적용되지 않았습니다.
